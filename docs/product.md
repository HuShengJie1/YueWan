# 产品说明

## 产品目标

「约玩 / MeetUp Vote」把微信群中零散的讨论结构化，让朋友更快确定参与者、候选活动、可用时间和最终安排。它不替代聊天工具，而是承接“形成决定”这一步。

## 典型场景

一群朋友计划周末见面：有人分享餐厅，有人建议密室或桌游，每个人空闲时间不同。发起人创建群组和一场约玩局，成员提交候选活动、表达活动态度、勾选多个可用时间，系统汇总后确认正式活动。

## 核心概念

- **User**：未来通过微信登录的用户。
- **Group / GroupMember**：朋友群组及成员关系，一个用户可加入多个群组。
- **Poll / Hangout**：属于某个群组的一次约玩决策，未来状态为 `draft`、`voting`、`confirmed`、`cancelled` 或 `finished`。
- **Proposal**：成员提交的候选活动，可带通用的外部平台、URL 和元数据。
- **ProposalVote**：对候选活动表达 `LIKE`、`OK` 或 `DISLIKE`，不是二元投票。
- **TimeOption / TimeVote**：明确的候选时间，以及成员可多选的可用时间。
- **Event**：约玩局确认后形成的正式活动。

## 未来业务流程

```text
创建或加入群组
→ 发起约玩局
→ 添加候选活动与明确时间
→ 活动投票与时间多选
→ 汇总结果
→ 确认正式活动
```

## MVP 范围

MVP 包括：用户、群组、加入群组、创建约玩局、候选活动、活动投票、时间投票、最终结果和确认活动。

MVP 暂不包括：聊天、AA 付款、AI 推荐、活动照片、好友系统、商业化，以及大众点评等平台的深度 API 集成。

当前初始化阶段不实现上述业务能力，只建立支持它们的工程边界。
